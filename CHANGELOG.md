# Changelog (agent-facing protocol/conventions)

- 2026-09-01: VehicleSample fmt 1 RPM is raw u16 (`rpm`, not `/50`); uint16 already covers typical engine RPM (<65k). Field renamed `rpmDiv50` → `rpm`. v6 unreleased, no fmt bump.

- 2026-09-01: VehicleSample msg (24, v6+, ephemeral): opaque self-versioned payload (leading fmt byte, append-only layout, ≤512B) relayed verbatim — payload fmt bumps need no server deploy. Replaces VehiclePos for v6 clients (dual-send keeps v5 peers seeing cars). Full spec + plugin replay design: docs/vehicle-sample-plan.md. Also verified: the live v5 client skips unknown msg types (warn-spam, not crash) — min_proto_version gating stays regardless.

- 2026-09-01: connection-handling hardening (src/): TCP keepalive on accept (dead peers reaped ~2 min; live conns were 45+ days stale); pre-auth/handshake read timeouts + 10s auth HTTP timeout; 4 remote-panic bounds checks in read_map_msg; room action-loop deadlock + expired-room leak fixed; player_left now by connection identity (reconnect no longer ghost-removes the new session); Admin_SetRoomPlayerLimit now updates the enforced limit (owner-sent). deploy.py: `deploy` auto-uses switch-mode waiter when legacy run.sh still owns the port (plain restart would AddrInUse-crash-loop). Wire protocol unchanged.

- 2026-08-31: idle-waiter fallback + deploy.py check now count only **active** connections (socket traffic within the idle window via `lastsnd`); the old binary never closes dead sockets, so scanner/zombie conns (Censys et al.) previously blocked the 0-conns idle condition forever. Sandbox suite extended (ss shim; zombie + live-conn cases) — 21/21 pass. US+AU staged & waiter-scheduled (switch mode); not switched yet — servers untouched until migration fires.

- 2026-08-30: deploy.py + DEPLOYMENT.md: prod deploy tool for map-together-{de,us,au}.xk.io (SSH aliases MapTogether{De,Us,Au}, restored in ~/.ssh/config). `just deploy` stages the binary atomically (-next.part → -next, md5-verified) then nohups a flock'd idle-waiter (/root/mt-idle-wait.sh) that restarts the systemd unit after 2 consecutive '0 players across 0 rooms' [stats] samples (fallback: 10 min of 0 connections for old binaries). `deploy.py setup` migrates the legacy `bash run.sh` setup (no supervisor, no logs, processes inside abandoned ssh session scopes) to map-together.service with Restart=always + journald. Local builds are compatible (max GLIBC_2.34 vs server glibc 2.38; only system libssl3/libcrypto3). Waiter logic covered by a shimmed-journald sandbox test.

- 2026-08-29: [stats] player/room count logged every 5 min. restart-when-idle.sh (+ just restart-when-idle) waits for 0 connections for N min (default 10; 30+ = lossless, room TTL is 30 min) then restarts the unit — the preferred deploy path; the opt-in idle-exit flag (--exit-when-idle-mins / MT_EXIT_WHEN_IDLE_MINS) still exists but the xsm unit no longer sets it (no periodic restarts).

- 2026-08-29: PlayerTestMode folded into protocol v6 (only v5 is live, so v6/v7 collapse into one unreleased bump; 0xFF 07 80 version bytes are no longer accepted). Ephemeral msg PlayerTestMode=23 (test-mode enter/leave + car-skin url); Player.proto_version captured at handshake; MapAction::min_proto_version() gate in the write loop stops relaying unknown types to old clients (they crash on them). v5 clients still accepted. Deploy servers BEFORE releasing the v6 plugin.
